# Product blueprint: T-Rex Runner（Chrome 离线小恐龙）

Product: T-Rex Runner（Chrome 离线小恐龙） · Official site: https://wayou.github.io/t-rex-runner/ · Studied on: 2026-10-14 · Goal: 给不会编程的人一个自己的恐龙小游戏：能跳、有仙人掌、能自己调速度

Reading guide: this blueprint describes **structure** (what the product does, how its objects relate, what its users go through), gathered only from public pages listed under Sources. It is a map for building your own product. It does not carry the original's interface, copy, images or brand, and nothing in it is copied from a non-public source.

## 0. 概要

T-Rex Runner 是 Chrome 浏览器断网页面上藏着的小恐龙跑酷游戏，被单独抽出来放在一个公开仓库里，用浏览器直接打开就能玩 [S1] {高}。玩家只做一件事：让恐龙跳过迎面而来的仙人掌和翼龙，活得越久分数越高，而游戏会随时间越来越快 [S2] {高}。没有账号、没有收费、没有关卡，核心体验就是「一个按键 + 越来越快」。

## 2. 信息架构

- 只有一个页面、一个画布，没有菜单、没有设置、没有登录 [S1] {高}
- 画布内部三层：背景（云、地平线）→ 障碍物 → 恐龙；画布外只有一个覆盖整屏的触控层 [S2] {高}
- 状态只有四种：等待开局、进行中、已撞毁、（移动端）街机模式 [S2] {高}

## 3. 核心对象与数据模型（推断）

| 对象 | 关键字段 | 关系 | 来源 | 置信度 |
|---|---|---|---|---|
| Runner（一局游戏） | 当前速度、已跑距离、最高分、是否进行中、是否撞毁、运行时长 | 拥有 1 个恐龙、1 个地平线、1 个计分器 | S2 | 高 |
| TRex（恐龙） | 位置、跳跃速度、是否在跳、是否下蹲 | 属于 Runner | S2 | 高 |
| Obstacle（障碍物） | 类型（小仙人掌/大仙人掌/翼龙）、位置、宽度、与下一个的间隙 | Horizon 持有 0..N 个 | S2 | 高 |
| Horizon（地平线） | 滚动位置、云列表、障碍物列表 | 属于 Runner | S2 | 高 |
| DistanceMeter（计分器） | 当前距离、最高分、最多 5 位数字 | 属于 Runner | S2 | 高 |
| Config（规则表） | 起始速度 6、加速度 0.001、速度上限 13、重力 0.6、起跳速度 12、开局无障碍 3000 毫秒、间隙系数 0.6 | 全局常量 | S2 | 高 |

## 4. 关键用户流程

- 流程 A（第一次玩）：打开页面 → 画面静止、恐龙待命 → 按空格 → 恐龙起跳同时游戏开始 → 3 秒后出现第一个障碍 [S2] {高}
- 流程 B（一局之中）：障碍从右向左移来 → 玩家按空格起跳 / 按下躲避 → 跳过则计分继续，速度每次更新 +0.001 → 撞上则画面定格 [S2] {高}
- 流程 C（结束与重开）：撞毁后显示结束面板和重开按钮 → 按空格 / 回车 / 点击 → 速度回到 6、距离归零、最高分保留 [S2] {高}
- 流程 D（触屏）：点击画面任意处等于按空格 [S2] {高}

## 5. 技术线索

- 纯浏览器前端：HTML + 一个 JavaScript 文件 + 一张精灵图，没有后端 [S1] {高}
- 代码来自 Chromium 项目，文件头声明 BSD 风格许可；仓库本身没有附许可证文件 [S1][S2] {高}
- 游戏循环用 requestAnimationFrame 按帧推进，速度与时间差相乘换算距离 [S2] {高}

## 7. 集成与生态

- 没有任何集成、API、导入导出或移动应用；它是浏览器彩蛋的独立复刻 [S1] {高}
- 存在于 Chrome 浏览器断网页面（原始出处）和若干公开仓库的复刻版本 [S1] {高}

## 8. 缺口与差异化机会

- 速度只能越玩越快，玩家没法把速度固定在自己舒服的档位：孩子和初学者玩不长，老手又嫌起步太慢 {推测}
- 没有任何可调项（速度、跳跃高度、障碍密度），想练反应的人没有「练习模式」 {推测}
- 规则对玩家不可见：「为什么越来越快」要读代码才知道；一个把规则摆在台面上的版本本身就是差异 {推测}
- 分数只在当次会话里，关掉就没了；v1 不必解决，但是明显的后续方向 {推测}

## 9. MVP 切分

**Users and the one job 用户与唯一任务:** 不会编程的人（和他们的孩子）：打开一个网址就能玩的恐龙跳仙人掌，而且能用滑块把速度调到自己想要的档位。

**Objects 对象 (<= 5):** 一局游戏（速度、距离、状态）、恐龙、仙人掌、速度设置（滑块值、是否自动加速）、计分

**Screens 画面 (<= 7):** 游戏画面（含控制条：开始、跳跃、重开、速度滑块、自动加速开关）、结束提示（叠在游戏画面上）

**Dropped from v1 and why 不做的:** 翼龙和下蹲（多一种障碍和一种动作，v1 只要「跳」一个动作）、昼夜反转、成就音效、街机模式、高清精灵图、触屏（v1 先在电脑浏览器跑通，手机点击作为 v1.1）、最高分持久化。

**Build order 构建顺序 (each step ends in something the user can click):**
1. 一个 HTML 文件：画布 + 恐龙方块 + 地面，点「开始」地面开始滚动——用户看到动起来。
2. 空格 / 「跳跃」按钮让恐龙起跳落地（重力 0.6、起跳速度 12 的手感）——用户能跳。
3. 仙人掌从右侧按间隙生成、碰撞即「游戏结束」、「重开」回到起点——用户能玩一整局。
4. 速度滑块 2–18 和当前速度数字：拖动即生效，固定速度——用户能调快调慢。
5. 「自动加速」开关：开启时从 6 开始，每次逻辑更新若速度 < 13 则 +0.001，逻辑更新固定每秒 60 次——用户能复现原版手感。
6. 计分和本局最高分——用户有目标。
7. 上线成一个网址（静态托管，零成本）——用户能把链接发给别人。

**Acceptance 验收 (v1 is done when):**
1. 用户做：打开网址点「开始」 → 应看到：仙人掌从右边移过来 → 机器验：页面加载无报错，开始后 2 秒内生成了障碍。
2. 用户做：按空格 → 应看到：恐龙跳起再落下，页面不滚动 → 机器验：跳跃后恐龙 y 值先减后回到地面；空格的默认行为被阻止。
3. 用户做：把滑块从 3 拖到 12 → 应看到：仙人掌明显变快，旁边数字显示 12 → 机器验：滑块值变化后游戏速度等于滑块值。
4. 用户做：撞到仙人掌，点「重开」 → 应看到：结束提示消失、又能玩 → 机器验：重开后距离为 0、速度回到设定值、状态为进行中。
5. 用户做：打开「自动加速」看数字 → 应看到：从 6.000 开始慢慢涨，到 13 附近停 → 机器验：从 6 起跑 0 / 1000 / 4000 / 10000 次更新后速度为 6.000 / 7.000 / 10.000 / 13.001（三位小数）。

**Learned vs own 学来的 / 自己定的:**
- 学来的（只学规则，不抄代码）：起始速度 6、每次更新 +0.001、上限 13（先判断再相加）、重力 0.6、起跳速度 12 [S2]；开局前等待第一次按键、撞毁后重开保留最高分 [S2]。
- 自己定的：画面与配色、恐龙和仙人掌的形状、控制条和滑块（2–18）、每秒 60 次逻辑更新、开局 1.5 秒无障碍、障碍间隙公式、计分换算、所有文案。

## 10. 我们不复制的东西

- 原版的界面、像素风精灵图、配色、字体和布局：恐龙、仙人掌、地面全部自己画。
- 原版的文案、截图、图片、音效，以及 Chrome / Chromium 的名字和标识。
- 原版仓库的任何代码：它的文件头声明 BSD 风格许可（宽松许可，非 copyleft），但我们只学了它的规则（起始 6、每次更新 +0.001、上限 13、重力 0.6、起跳 12、开局 3 秒无障碍），实现全部重写。
- 没有用任何非公开材料：没有登录、抓包、反编译或泄露资料。
